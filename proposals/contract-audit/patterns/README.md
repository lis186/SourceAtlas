# 錨定模式（Anchor Patterns）

Step 0.7 確定性合約預掃描使用的模式定義檔。

## 格式

每行一個規則，`#` 開頭為註解：

```
類別|名稱|grep pattern|說明
```

- **類別**：S（同步）、N（通知/事件）、L（生命週期）、D（依賴）、E（例外）、C（取消）
- **名稱**：模式的唯一識別符，用於 anchor-contracts.md 中的顯示
- **grep pattern**：`grep -E` 相容的正規表達式
- **說明**：人類可讀的描述

## 與語言插件的關係

patterns 檔案是語言插件（`prompts/languages/*.md`）§1-3 的**機器可讀版本**：

| 來源 | 涵蓋類別 | grep 可覆蓋性 |
|------|---------|-------------|
| §1 通知/事件原語 | N, D | 高 — API 名稱固定 |
| §2 同步原語 | S | 高 — 併發原語有限 |
| §3 生命週期 | L | 中高 — 框架 hook 名稱固定 |
| §5 Effect 防火牆 | M, P | 低 — 語義型，grep 無法捕捉 |
| §7 Sprout/Wrap | D | 中 — import/singleton 可偵測 |

**設計原則**：S/N/L/D/E/C 六類可用 grep 高覆蓋率偵測。M（Mutation）和 P（Protocol/型別）兩類是語義型合約，只能由 LLM 發現——這是刻意的分工。

## 如何新增模式

### 從 LLM 結果回饋

1. 檢查 LLM 產出的合約是否屬於 S/N/L/D/E/C 類
2. 確認該合約有可 grep 的結構性標記（API 名稱、關鍵字等）
3. 在對應的 `.patterns` 檔案中新增一行
4. 在至少 2 個真實專案上驗證誤報率

### 新增語言

1. 建立 `{language}.patterns` 檔案
2. 從對應的語言插件 §1-3 提取可 grep 的原語
3. 在真實專案上測試命中率
